# 在线控制器开发与运行边界复核

本轮依次完成数学口径修正、循环代价对照、运行压力测试、新能源关联分析、预测区间诊断和全新环境验证。所有新结果是既有年份公开后的开发复核；原冻结代码、模型、阈值和 2021 年验证协议不变。

## 两阶段规划与准入结果

原控制器使用加权目标 `z + 0.001*吞吐`，不能声称吞吐项只在等价峰值方案中打破平局。新模块先最小化预测窗口峰值 z，再约束窗口峰值不超过 z_min + delta，最小化窗口吞吐。delta 为 0 时是严格优先级；100/250/500 MW 则是明确的工程取舍参数，并非全年实际峰值保证。

新版保留原点预测、上界放电门槛、动态软储备和极端释放、功率和效率、日末 SOC 恢复。每小时执行第一步，不读当前或未来真实负荷作决策；动作转换消除同时充放电，逐小时核验物理约束。全周期最优性证明仍限于离线基准，新版滚动规划不能沿用它宣称全年最优。

在运行参数网格前，保存开发协议及来源哈希。准入规则只使用原验证期：最高点不高于原冻结新动态 +1 MW、P95 不高于 +50 MW；满足者选择吞吐最低配置，否则保留原控制器。该记录是已知数据下的透明开发记录，不称首次未触碰预登记。

## 运行压力测试

事先固定每季度 1/4/7/10 月 8 日开始的七日周。每周比较原冻结新动态与 250 MW 候选，在名义、预测传递滞后 1/3 小时、连续六小时预测缺失、整体预测偏差 ±1000 MW、功率降至 70%、效率降至 0.85 的条件下评价。另对候选进行七日跨午夜连续运行，周末恢复初始电量；原日独立控制器对此不适用，不混用日重置作为连续参照。

四周、九个情景共 68 条已求解轨迹，全部物理约束核验通过、最大终端偏差低于 1e-5 MWh。该结果只验证这些构造情景的可行性。2021-07-08 周原控制器在 3 小时预测传递滞后下最高点比名义高约 405.08 MW，表明效果会退化。某些周滞后或功率下降反而降低最高点，反映补电与状态路径的变化，不能推断降低功率或增加延迟普遍更好。

滞后情景延迟既有预测的到达，对齐旧发布中对应目标小时的预测。超出六小时发布范围时，沿用最后发布时距的点预测和区间，不读真实负荷。每周带前一天预测作为暖启动。这里模拟的是预测传递滞后，不是重新训练具有延迟量测特征的模型。没有测试跨周连续运行、真实传感器故障、网络拓扑或调度授权，不将其标作现场验证。

## 新能源关联与爬坡证据

高新能源占比阈值由原完整验证期新能源实际出力/总负荷的 q90 固定，为约 61.98%。各策略按完全相同小时对齐实际光伏、风电、负荷，仅做事后描述。

2021 年原冻结新动态在高占比时段充电 1,250 MWh，占总充电约 0.165%；绝对净负荷爬坡 P95 从 5,836.62 增至 5,867.50 MW/h，最大上爬坡未改善。这说明当前策略的强证据是极端削峰，不足以宣称主动对齐新能源高出力充电或平滑爬坡。所有候选及三段数据指标均在 `renewable_alignment_metrics.json`。

充电时段与新能源出力的关联不能识别充电电量的来源。当前公开数据只有实际发电量，缺少可用出力、弃电量、网络约束和反事实，不能计算“减少弃风弃光”。后续若把消纳作为独立目标，需新增可用新能源预测及相应约束，另做开发和新的验证。

## 区间分组诊断与滚动校准

按六个预测时距、四季度及高负荷子集，比较冻结区间与一个固定规则的滚动版本。滚动半径为发布时已经观测到的过去 720 小时绝对预测误差 q90，至少需 168 条；否则用冻结半径。真值标记小时 s 对应 [s,s+1h)，因此其残差只能在 s+1h 及之后进入校准。测试通过修改未来残差核验早期区间不变。

2021 年一小时整体覆盖率由 88.03% 变为 89.82%，更接近名义 90%。但 Q3 高负荷子集只有 37 小时，覆盖率由 91.89% 降至 83.78%；Q1/Q4 高负荷覆盖率提高但区间变宽，平均区间评分也变差。因此滚动版本尚未替代冻结区间，也未反馈控制器。

同时报告区间宽度和中央 90% 区间评分 `width + 20*max(0, abs(error)-radius)`，避免靠扩大区间提高覆盖率。这是一个固定窗口规则的已知年复核，没有网格挑选最优半径，也没有任何概率保证。后续需用新的独立时段检验条件覆盖和决策影响。

## 工程可靠性与复现

OPSD 下载新增带超时、有限重试、内容长度与 CSV 字段检查的原子落盘。失败时清除临时 `.part` 文件并保留原缓存，支持可选快照 SHA-256 校验。冻结的 2021 下载脚本不修改。仪表盘缺少必需工件时明确列出缺失文件及复现路径，不展示半成品结果。

在 Windows x64 新建无系统 site-packages 的 Python 3.13.5 虚拟环境，按 `requirements.txt` 安装依赖；依赖一致性、单元测试、最优性证书、仪表盘和开发轨迹审计通过。完整安装清单和核验回执附于 `outputs/development/clean_environment_*`。这不等于在全新环境重下载全部原数据并重训练，也不证明 Linux/macOS 已验证。

```powershell
python scripts/run_controller_development.py
python scripts/run_operating_stress.py
python scripts/audit_energy_and_intervals.py
python scripts/audit_development.py
python -m venv tmp/clean-runtime
tmp/clean-runtime/Scripts/python.exe -m pip install -r requirements.txt
python scripts/verify_clean_environment.py --python tmp/clean-runtime/Scripts/python.exe
```

首次开发运行需要随包附带的冻结模型、原校准和预测工件。审计从小时轨迹重算峰值、P95、吞吐、损耗、SOC、准入结果、运行情景、区间宽度与评分及新能源关联。原始证据预检继续核对冻结 SHA-256。

## 后续开发重点

保留主版本的最高点下界证据，下一版明确“容许多少峰值代价换多少循环减量”的应用偏好；若选择 250 MW 取舍，应明确它放弃现有峰值最优。另研究新能源感知补电和更稳健的跨日终端价值，而不是继续按已知 2021 年最高小时调参。所有新控制器和滚动区间均需在新时段锁定后检验；新地区、可用出力、电价、退化和网络信息尚待合法获取。
